2 · Brand and naming changes

This is the load-bearing section. Apply throughout the rulebook; nothing else in the brief matters if this sweep is incomplete.

2.1 The framing pivot

Old framing: "Thresan is the universe; Skyflag is the game within it; Kaleo Edition is the first setting."
New framing: Thresan™ is the game (rules-level identity, like chess). Skyflag is its current edition — the pieces, the boards, and the storyboard set in the world of Kaleo. Future editions of Thresan keep the rules and change the storyboard.

Locked 2026-05-13 across every public-facing surface. Reflect the same framing throughout the rulebook.

2.2 Title-form usage

  • Long form: Thresan: Skyflag.
  • Short form: Thresan (when context is clear), or Skyflag (when specifically the edition).
  • Trademark: ™ goes on Thresan only. Never on Skyflag alone. Apply ™ to the first prominent occurrence per major section (cover, front-matter, foreword), not to every instance.

2.3 Sweep targets

Drop every instance of "Kaleo Edition" as a subtitle. Three places it commonly appears:

  • Title page lockup → replace with Thresan: Skyflag — Rulebook v21.
  • Running footer → replace with Thresan: Skyflag · Rulebook v21 · §N.
  • "About this edition" / colophon page → rewrite per §2.4.

In running prose, replace any "first game in the Thresan universe" phrasing with "current edition of Thresan."

2.4 New colophon paragraph (front matter)

Recommended draft text — edit as needed:

"Thresan is a strategy game. Skyflag is its current edition — the pieces, the boards, and the storyboard set in the world of Kaleo. The rules in this book describe Thresan; the names, art, and narrative describe Skyflag. Future editions of Thresan may rename the pieces, redress the boards, and rewrite the world. The rules will not change."

3 · Lessons learned during the build

Surfaced during construction of the web prototype, brand surfaces, and physical-edition concept work. Most are already folded into v20; verify before final layout.

3.1 Piece count (the v19.1 ambiguity that burned testers)

v19.1 was ambiguous about piece counts. Make it explicit on the setup page:

  • 4 pieces per player (8 total): one Captain, one Soldier, one Rover, one Pilot.
  • Each piece is distinct in role, movement, and starting position. Pieces are not interchangeable tokens.

3.2 Cross-Board Rule edge cases

Several edge cases emerged during app development that should be codified into the rulebook proper rather than living in errata:

  • Lift-during-capture sequencing — define which resolves first.
  • Simultaneous claim-seal threat resolution — when one move threatens multiple seals in a single turn.
  • Nexus capture preconditions — required state of the Captain piece for the Nexus-win path to be legal.

3.3 Win condition language

Clarify both win paths with sentence-level precision. Recommended phrasing:

  1. Path of seals: capture all three of the opposing clan's claim-seals — one on each plane (Terran, Meridian, Empyrean).
  2. Path of the Nexus: land your Captain on the Caelum Nexus at Space(3,3).

Specify what happens if both conditions are achieved on the same turn (default: seals resolve first; document it).

3.4 Terminology consistency

Choose one term per concept and stick to it across the rulebook:

  • "claim-seal" in lore prose; "flag" in mechanical rules sections. Acceptable to use both if labeled clearly; pick one if a single voice is preferred.
  • "Lift" with capital L when naming a Lift mechanism; lowercase when used as a verb.
  • "Nexus" always capitalized when referring to the Caelum Nexus square.

3.5 Time control note

If supporting tournament play (or even friendly online multiplayer with optional clocks), add a one-page appendix on time controls: per-move budget, per-game budget, increment. Currently absent from v19.1.

3.6 Promotion lore sidebar

Add the medical-event flavor framing for Soldier-to-Captain promotion (Durren → Dantec transformation) as a lore sidebar. Surfaced during app development as a memorable narrative beat that strengthens the constructive-proof framing.

4.2 Typography

  • Wordmark: refined geometric type, wide tracking (0.22em on THRESAN, 0.04em on SKYFLAG subhead). Currently raster only; commissioning a proper font file is flagged in §8.
  • Body: Crimson Pro (serif) or Inter (sans). Pick one for the print rulebook. Inter recommended for clarity in mechanical rules; Crimson Pro for lore sidebars and the story foreword.
  • Section headings: Inter Bold, Aether Gold, with a 2pt rule underline in Aether Gold.
  • Monospace (for coordinate notation like Space(3,3)): JetBrains Mono or Menlo.

4.3 Sigil placement

  • Cover — large sigil centered above wordmark lockup.
  • Section breaks — small sigil decorative element, centered.
  • Running footer — minimal: sigil glyph + page number.

4.4 Page layout

  • Trim size: Letter (8.5×11) for first print. Switch to A5 if going to a games-specific publisher later.
  • Margins: 0.85in all around, 1.0in bottom for footer.
  • Binding: saddle-stitch for ≤40 pages; perfect bind for ≥48.
  • Cover material: matte black with gold foil for the sigil — fits the "monastery, not tech" aesthetic. Sample on press before full run.

4.5 Diagrams

  • Every diagram uses the brand palette.
  • Each diagram annotated with the relevant rule section number (e.g., see §4.2).
  • Board representations: choose isometric or top-down — pick one and use it throughout. Recommended: top-down for mechanical rules (cleaner), isometric for chapter openers (more evocative).

5 · Concept framing

5.1 Tagline placement

"Three worlds. One proof." appears in three places:

  • Cover (lower third, scripted/handwritten font for warmth).
  • Last page (centered, restrained).
  • Each section divider as a small footer mark.

5.2 Constructive-proof framing

In the introduction, frame the game as a constructive proof — distinct from chess's contradiction proof. Both Thresan win conditions are positive demonstrations of reach across the three planes, not eliminations of the opponent. This is the conceptual hook that distinguishes Thresan from its eight-by-eight ancestor. Cross-reference{' '} thresan.io / "The proof of three" for full framing — but condense to one paragraph for the rulebook intro.

5.3 Tone

  • Authoritative but warm. This is a rulebook, but written by one person, for two people sitting across a table.
  • Avoid corporate plural ("we") in rule text. First-person OK in foreword and acknowledgments.
  • Lore sidebars set in italic Crimson Pro, visually distinct from rule text. Never blur the line between rule and lore — readers need to know which is binding.

6 · Distribution

6.1 File deliverables

  • Print-ready PDF — CMYK, 300 DPI, embedded fonts, 0.125in bleed, crop marks.
  • Web PDF — RGB, 150 DPI, hyperlinked TOC, smaller file size for fast download.
  • EPUB — optional for v2; v1 can skip if scope is tight.

6.2 Hosting

  • Print-ready: not on website; sent to printer directly.
  • Web PDF: linked from playskyflag.com/help ("Download the rulebook").
  • Press kit: include web PDF in the assets grid at playskyflag.com/press.

6.3 Version control

  • Repository copy: docs/rulebook-v21.pdf.
  • Source HTML: keep scripts/rulebook-v21.html updated in lockstep.
  • Markdown source: consider extracting if this becomes a living document with regular edits.
